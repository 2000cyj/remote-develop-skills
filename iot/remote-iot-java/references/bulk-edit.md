# 批量改码与补注释

适用：批量补 Javadoc、全仓重命名类 / 枚举 / 方法、批量替换 import、统一字段命名（`message` → `msg`）这类**跨多文件**的机械改动。

## 类注释规范

```java
/**
 * 一句话描述
 *
 * @author dingyunwei
 */
```

- 描述用**简短名词短语**（"统一响应结果" / "协议编解码器接口" / "物模型数据类型枚举"），与包内既有风格对齐；不要写成完整句子
- **`@author` 沿用该文件原值**，不要强行统一成 `dingyunwei`（仓库里存在 `dwx` 等其它作者）
- **已有描述的类不动**；只有 `@author` 没有描述的，补一行描述；完全没有类级注释的，才新建整块
- 补完后类级 javadoc 应当紧邻类型声明（注解可以隔在中间，但**不要**多出第二个 javadoc 块）

## 脚本化改码的四个坑（都真实踩过）

**① 拼接丢换行 → 产出语法错误的 Java**

用 `'\n'.join(lines) + rest` 拼字符串时，`join` 结果**不带尾换行**，会把 `*/` 与下一行粘成 ` */@Data`，直接编译失败。

→ 全程用行数组操作，最后一次性 `'\n'.join(lines)`；拼接处显式补换行。

**② 回溯找 javadoc 时没跳过空行 → 出现两个 javadoc 块**

有的文件 javadoc 与注解之间有空行（`*/\n\n@Getter`）。只判断"上一行是 `*/`"会漏判，结果旧 javadoc 没被替换、又插入一个新块。

→ 回溯时先跳过空行再判断是否命中 `*/`。

**③ `git add -A` 扫进别人的在制品**

用户在同一 workspace 并行编辑时，`git add -A` 会把对方**未完成的**文件一起暂存（本次就误扫进了对方的前端改动与 `.codex/`）。

→ 显式 `git add <path>`；提交前用 `git diff --cached --name-status` 逐条核对。

**④ 暂存区半成品 → 提交出"文件名与类名不一致"的坏代码**

`git mv` 后只暂存了重命名，**类名改动还留在工作区**。直接 `git commit` 会提交出「文件叫 `ErrorCode.java`、里面却是 `public enum ResultCode`」的版本。

→ `git status --porcelain` 首列 `R` 表示已暂存的重命名、次列 `M` 表示工作区还有改动；提交前必须让索引与工作区一致（`git add -A <目标路径>`）。

## 全仓重命名的检查清单

1. 新名全局唯一，不与既有类重名
2. **类名与文件名一致**
3. 全仓残留归零：旧名在 `.java` / `.md` / `.xml` / `.yml` 里 grep 无结果
4. **导入 / 使用一致性**：扫描"用到了但缺 import"与"import 了但未使用"
   - 注意**全限定名内联**写法（如 `new com.github.dingdaoyi.core.exception.Xxx(...)`）不需要 import，会造成误报
5. 字符串硬编码 / 反射查找：`valueOf("OldName")`、枚举名写进配置或 DB 的情况
6. **枚举类**：常量个数与码值**逐个比对**，不能只改类名
7. 文档同步：`README.md`（中英双份）、`.planning/`、`CHANGELOG.md` 里的旧名

## 批量改完的强制自检

至少跑这 5 项，再抽样看 `git diff`：

```
1. 每个文件类型声明前恰好 1 个 javadoc 块
2. 花括号配平
3. 注释块配平（/* 与 */ 数量相等）
4. 无 "*/" 与后续字符粘连（正则 /\*/\S/）
5. 行尾一致（CRLF / LF 不混排）
```

## 先小样本验证

批量脚本**先在 2-3 个文件上跑**，确认 diff 正确再全量。全量跑完发现结构错误时，**整体回滚重做**（`git checkout -- <路径>`），不要逐个手补 —— 手补容易漏，且会把不一致的格式留在文件里。

## 合并两个同义类（如两个异常类）

合并前必须核对四件事，缺一件都会炸：

| 检查项 | 漏掉的后果 |
|---|---|
| **构造器覆盖**：新类是否提供了旧类的**每一个**构造器签名 | 旧调用点编译失败（本次 `(ErrorCode, String)` 双参构造器就漏了，33 处调用） |
| `@ExceptionHandler(Xxx.class)` 分支 | 异常落到兜底分支，**业务错误码丢失**（变成 500） |
| `catch (Xxx e)` 显式捕获点 | 编译失败 |
| 继承关系 | 旧类若非 final 且有子类，新类 final 会断掉继承 |

替换后确认调用方语义不变：`getMessage()` 是否仍返回提示文本（`@Getter` 生成的 `getMsg()` 与覆写的 `getMessage()` 要一致）。
