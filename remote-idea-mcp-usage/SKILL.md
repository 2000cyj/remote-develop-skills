# IDEA MCP 操作与数据库权限

## 核心规则

按以下优先级判断，前一条覆盖后一条：

1. **数据库硬边界**：只有 IDEA 数据源连接名去除首尾空白后、不区分大小写完整等于 `dev` 的数据库可以写；其他数据库只能读。
2. **代理范围边界**：全权限只覆盖当前已开启 IDEA MCP 代理所暴露的开发环境。
3. **任务范围边界**：权限表示无需重复请示，不表示可以执行与当前任务无关的操作。

不得用“IDEA MCP 有全权限”绕过数据库只读规则，也不得用 IDEA 终端、运行配置或脚本把操作扩展到代理环境之外。

## 当前代理范围

开始操作前，通过 IDEA MCP 返回的项目信息确认当前代理实例及项目根目录。以下目标属于代理范围：

- 当前 IDEA 实例已打开项目的根目录、模块及其文件。
- 当前项目的索引、构建模型、依赖、运行/调试配置和测试配置。
- 当前项目拥有的本地开发进程、端口和服务。
- 当前项目仓库的本地 VCS 根目录、工作树、暂存区和本地引用。
- 当前代理中配置的数据源；其写权限仍由“数据库权限”一节单独决定。

以下情况不属于代理范围：

- 其他 IDEA 实例、未打开的项目、其他仓库或项目根目录外的文件。
- 与当前项目无关的本机进程、服务、凭据和系统配置。
- 远程 Git 仓库、代码托管平台、PR/MR 和其他外部系统；它们不会因为配置成当前仓库的 remote 而进入代理范围。
- 测试、预发布、生产或其他外部环境中的可变状态；数据库只读访问除外。
- 仅仅因为 IDEA 终端在技术上能够访问到的路径、网络或系统资源。

无法从 IDEA MCP 信息确认目标是否属于当前代理范围时，不执行变更；先说明无法确认的目标和缺失信息。

## 代理范围内的权限

当前任务需要且目标位于代理范围内时，可以直接使用 IDEA MCP 执行其暴露的任何操作，无需为操作类型再次请求权限，包括：

- 读取、创建、修改、重命名、移动或删除项目文件。
- 搜索符号、分析引用、重构代码和检查问题。
- 构建、编译、重新加载依赖、刷新索引和运行测试。
- 启动、停止、重启和调试当前项目的本地开发配置。
- 执行当前项目所需的 IDEA 终端命令。
- 操作当前项目的本地版本控制状态。

全权限不扩大任务本身。仍然只执行完成用户目标所需的操作，不顺手修改无关代码，不覆盖、回滚或清理用户已有改动。对删除、重置、批量修改等高影响操作，先核对准确目标和影响范围；如果它确实属于用户要求和代理范围，可以执行，不需要形式化二次确认。

远程仓库写入、PR/MR 或其他外部系统操作不由本 skill 的代理内全权限授权；只有用户另行明确要求且上层规则允许时，才作为独立任务处理。

### 创建文件与 Git 纳管提示

通过 IDEA MCP 创建文件时，默认只创建工作区文件，**不得主动执行 Git add、暂存、加入版本控制或修改 Git 纳管状态**。若 IDEA 弹出“是否将新文件加入 Git 管理”之类的原生 UI 选项，期望结果是**取消并保持文件未跟踪**。

当前 IDEA MCP 的创建文件接口只支持 `path`、`text`、`overwrite`，**不支持**控制该弹窗、指定“默认取消”、自动关闭弹窗，或修改 IDEA 的 VCS UI 首选项。因此：

- 不得把“代理范围内可操作本地版本控制状态”解读为创建文件后自动加入 Git。
- 不得通过 IDEA 终端、脚本、键盘/鼠标自动化或修改 IDEA 设置绕过 MCP 能力边界来关闭或操纵该弹窗。
- 若弹窗实际出现而 MCP 无法操作，应停止在文件创建完成的状态，不执行 Git 纳管，并报告“文件已创建、未加入 Git；原生 IDEA 弹窗需由用户手动取消或在 IDEA 设置中配置”。
- 用户明确要求纳入 Git 时，仍需按独立版本控制任务处理，先核对目标文件和工作区状态；本节的默认“不加入 Git”不等同于禁止用户明确要求的 Git 操作。

## 数据库权限

### 环境判定

只使用 IDEA MCP 中显示的**数据源连接名称**判定数据库权限：

1. 读取当前操作所用连接的名称。
2. 去掉名称首尾空白。
3. 按不区分大小写的方式与 `dev` 做完整匹配。

只有用户在 IDEA 中创建或命名、且完整匹配成功的连接才是 `dev` 数据库。例如 `dev`、`DEV` 可写；`dev-copy`、`test-dev`、`development`、空名称和无法确认名称的连接都不是 `dev`，只能读。

<!-- ponytail: 按用户的连接命名约定只检查数据源名称；若命名约定变化，应升级为显式环境标签校验。 -->

不得根据主机名、schema 名、数据库内容或名称中包含 `dev` 来推断写权限。代理不得通过新建、复制或事后重命名数据源来取得 `dev` 写权限；需要新的 `dev` 连接时，由用户在 IDEA 中创建或命名后再重新读取。

### 权限矩阵

| IDEA 数据源连接名 | 查询 | 新增 | 修改 | 删除 | DDL/管理操作 |
| --- | --- | --- | --- | --- | --- |
| 完整匹配 `dev` | 允许 | 允许 | 允许 | 允许 | 仅在当前任务明确需要时允许 |
| 其他或无法确认 | 只读 | 禁止 | 禁止 | 禁止 | 禁止 |

数据库规则是硬限制。即使数据库账号本身有写权限，或者用户临时说“授权继续”，也不得通过非 `dev` 连接执行写入、结构变更或管理操作。若用户要求修改非 `dev` 数据库，应拒绝执行并说明该连接按本规则只读。

### `dev` 数据库操作

当前任务需要时，可以直接在 `dev` 连接执行增删改查，无需再次询问：

- 执行前确认连接名称、schema、表、条件和预计影响行数。
- `UPDATE` 和 `DELETE` 先用同条件查询确认目标记录。
- 除非任务明确要求全表操作，否则写语句必须使用明确条件。
- 能使用事务时优先使用事务；执行后查询验证实际结果。
- DDL、权限或其他管理操作必须是当前任务明确需要的内容，不得从普通 CRUD 请求中自行扩展。
- 不在输出、日志或代码中暴露密码、Token、完整连接串或不必要的敏感数据。

### 非 `dev` 数据库只读操作

非 `dev` 连接只允许无副作用的读取：

- 允许读取数据库、schema、表、字段、索引、约束和执行计划等元数据。
- 允许执行限定字段、条件和返回行数的 `SELECT`、`SHOW`、`DESCRIBE` 及不实际执行语句的 `EXPLAIN`。
- 禁止 `INSERT`、`UPDATE`、`DELETE`、`MERGE`、`CREATE`、`ALTER`、`DROP`、`TRUNCATE`、`GRANT`、`REVOKE` 和批量导入。
- 禁止 `SELECT ... FOR UPDATE`、会产生写入或锁定副作用的函数/存储过程，以及可能包含写语句的多语句脚本。
- 无法证明语句无副作用时，按写操作处理并拒绝执行。

不得通过事务、临时表、脚本、函数、触发器、存储过程或调用外部工具绕过只读限制。

## 执行流程

1. 调用前提示正在使用 IDEA MCP，并说明目标操作。
2. 确认当前代理实例、项目根目录和目标是否在代理范围内。
3. 检查工作区状态，识别并保留用户已有改动。
4. 创建文件时只写入工作区；不主动纳入 Git。若 IDEA 原生 Git 纳管弹窗出现而 MCP 无法控制，保持未跟踪并报告给用户。
5. 涉及数据库时，先按连接名称完成 `dev`/只读分类，再检查 SQL 是否符合权限。
6. 执行完成当前任务所需的最小操作；不要因为权限充分而扩大范围。
7. 使用 IDEA 问题检查、相关测试、局部或必要范围的构建验证结果。
8. 调用结束时报告完成时间或长任务的当前进度，以及实际操作范围、验证结果和未验证内容。

构建或检查通过只代表实际执行的范围通过。数据库查询成功也不代表该连接拥有写权限。

## 快速检查

- [ ] 当前 IDEA MCP 代理实例和项目根目录已确认。
- [ ] 目标属于当前代理暴露的开发环境。
- [ ] 操作与当前任务直接相关，且不会覆盖用户已有改动。
- [ ] 创建文件仅写入工作区，未主动加入 Git；若出现 MCP 无法控制的 IDEA 原生纳管弹窗，已明确保留未跟踪并报告。
- [ ] 数据源连接名已读取并按完整名称匹配，未用包含关系猜测 `dev`。
- [ ] 非 `dev` SQL 已确认无写入、锁定或其他副作用。
- [ ] `dev` 写操作已核对目标和影响范围，并安排结果验证。
- [ ] 已提示 MCP 调用，并准备报告完成时间或进度。
