# IDEA MCP 使用范围与操作规范

## 1. 文档目的

本文规定 IDEA MCP 在本项目中的使用范围、默认权限、认证要求和验证方式，适用于通过 JetBrains IDEA MCP 对项目代码、构建工具、运行配置和数据库执行操作的场景。

项目范围：`D:/OB/ob_web/packages/micro/cashier`

本文优先保障以下原则：

- 最小权限：只使用完成当前任务所需的最低权限。
- 最小范围：只读取、修改、构建和加载与当前任务直接相关的范围。
- 默认安全：不主动执行不可逆、跨环境或可能影响其他用户的操作。
- 可追溯：变更前后检查工作区，记录实际执行范围和验证结果。

## 2. 操作权限分级

### 2.1 默认允许

以下操作在当前项目范围内可以直接执行：

- 读取项目文件、目录、模块和运行配置。
- 搜索代码、符号、引用、调用关系和依赖关系。
- 分析文件错误、警告、类型问题和静态检查结果。
- 读取 Git 状态、差异和最近提交记录。
- 修改用户明确要求的文件，以及完成需求所必需的直接关联文件。
- 对修改范围执行局部类型检查、局部编译、局部构建和相关测试。
- 读取数据库元数据、表结构、索引和约束。
- 在授权数据库上执行受限查询。

### 2.2 需要用户确认

执行以下操作前必须说明操作对象、范围和影响，并获得用户明确确认：

- 全项目或跨模块构建。
- 全量 Maven reload、全量依赖解析或大范围索引刷新。
- 扩大代码修改范围，涉及用户未明确要求的模块或目录。
- 修改环境变量、运行参数、服务端口或工作目录。
- 安装依赖、修改 `package.json`、锁文件或构建工具配置。
- 启动、停止或重启本地服务，尤其是可能占用共享端口的服务。
- 执行数据库批量删除、批量更新、DDL 或其他不可逆操作，即使目标是 `dev` 数据库。
- 访问项目范围之外的仓库、目录、服务或数据库。
- 执行网络请求、上传文件或向外部服务发送项目数据。

### 2.3 必须用户认证和授权

以下操作不允许仅依据普通任务描述执行，必须由用户明确认证和授权：

- 对非 `dev` 数据库执行任何写入、结构变更或管理操作。
- 对测试、预发布、生产或其他非开发环境执行写操作。
- 执行生产环境重启、发布、回滚、数据修复或权限变更。
- 修改或读取受保护的密钥、密码、Token、证书和连接凭据。
- 执行 Git `commit`、`push`、`reset`、`rebase`、删除分支或创建 PR。
- 删除项目文件、目录、数据库对象或其他不可恢复资源。
- 执行跨项目、跨仓库或超出当前工作区的高影响操作。

用户授权必须明确包含：目标环境、目标对象、操作类型和允许的影响范围。诸如“随便处理”“按需要操作”等模糊表述不能视为高风险操作授权。

## 3. 代码读取与修改规范

### 3.1 修改前分析

修改代码前必须先完成以下检查：

1. 确认当前项目和目标文件路径。
2. 读取相关文件、符号定义、调用方和被调用方。
3. 识别修改涉及的模块、路由、接口、状态、组件和测试。
4. 检查工作区状态，确认是否存在用户已有的未提交修改。
5. 判断是否可以通过最小修改完成需求。

### 3.2 修改范围

- 只修改用户明确要求的文件，或实现需求不可避免需要修改的直接关联文件。
- 不得因为发现代码风格问题而顺手重构无关代码。
- 不得执行全仓库格式化、全局替换或无关依赖升级。
- 不得覆盖、回滚、删除或重置用户已有的未提交修改。
- 重命名类、方法、字段和变量时，优先使用 IDEA 的符号重构能力，避免普通文本替换造成遗漏或误改。
- 修改配置时只调整当前需求所需的最小配置项，并保留原有配置意图。
- 处理敏感信息时不得把密钥、密码、Token 或完整个人数据写入代码、日志或本文档。

### 3.3 文件创建与删除

- 新建文件前确认目标目录和文件名不存在冲突。
- 删除文件或目录必须得到用户明确确认，除非该删除是用户明确要求的一部分。
- 生成临时文件、构建产物或诊断文件时，应优先放在临时目录，并在任务结束时清理不再需要的文件。

## 4. 构建与编译规范

### 4.1 最小范围原则

代码构建只允许覆盖本次修改涉及的范围，优先级如下：

1. 单文件问题检查或单文件编译。
2. 当前修改所在模块的局部构建。
3. 当前模块直接依赖的最小必要模块构建。
4. 只有局部构建无法验证时，才考虑扩大到更大范围。

默认禁止直接执行全项目构建。需要扩大构建范围时，必须先说明：

- 为什么局部构建无法完成验证。
- 将要构建的模块和依赖范围。
- 预计耗时和可能影响。
- 是否会生成或修改锁文件、构建产物及其他工作区文件。

### 4.2 构建结果处理

- 构建失败时先判断失败是否由本次修改引起。
- 优先修复当前修改导致的问题，不得为了通过构建而扩大无关改动。
- 构建成功只表示指定构建范围通过，不得表述为全项目无问题。
- 构建产物不得自动提交到 Git，除非用户明确要求。
- 构建过程中发现用户已有改动，应保留这些改动并在结果中说明。

### 4.3 前端项目约定

本项目是 Vue 3 + Vite 微应用。执行本项目构建或开发验证时，应遵循仓库现有约定：

- 先确认共享组件库构建产物是否存在及是否满足当前验证需要。
- 只构建 `cashier` 子应用或当前修改涉及的最小范围。
- 修改共享组件后，不得假设本项目会自动获得最新共享产物；需要按项目约定重新构建共享组件库时，先说明该范围扩大。
- 构建、测试或开发服务产生的临时文件不得混入业务源代码提交。

## 5. Maven 依赖加载规范

虽然当前子应用主要使用前端工具链，但当 IDEA MCP 处理 Maven 项目或关联后端模块时，必须遵循以下规则：

- Maven 加载默认采用小范围、按需加载策略。
- 优先加载当前修改所在模块及其直接必要依赖。
- 默认不执行整个 Maven 多模块工程的全量 reload、全量依赖解析或全量索引。
- 不得为了代码补全或单个类型解析而无理由加载全部模块。
- 需要全量 Maven 加载时，必须先说明原因、范围、预计耗时和资源影响，并获得用户确认。
- 不得擅自修改 Maven 版本、插件版本、依赖版本或仓库配置。
- 不得擅自删除本地 Maven 缓存或重新生成全部依赖缓存。
- 依赖加载失败时，先检查当前模块的坐标、直接依赖和仓库配置，再决定是否扩大加载范围。

## 6. 数据库权限与操作规范

### 6.1 数据库权限矩阵

| 数据库环境 | 查询 | 新增 | 修改 | 删除 | DDL/管理操作 |
| --- | --- | --- | --- | --- | --- |
| `dev` | 允许 | 允许 | 允许 | 允许，但需谨慎 | 需要用户确认 |
| 非 `dev` | 允许，只读 | 禁止 | 禁止 | 禁止 | 禁止 |
| 非 `dev`，已完成用户认证 | 按授权范围 | 仅按明确授权 | 仅按明确授权 | 仅按明确授权 | 仅按明确授权 |

### 6.2 `dev` 数据库

`dev` 数据库允许执行增删改查，但仍必须遵守以下限制：

- 删除、批量更新、批量删除、DDL 和不可逆操作执行前必须二次确认。
- 优先使用带明确条件的语句，禁止无条件执行高影响写操作。
- 执行写操作前先用查询确认目标记录和影响数量。
- 能使用事务时优先使用事务，并在执行后验证结果。
- 不得把 `dev` 数据库中的敏感数据复制到代码、日志、聊天内容或文档。
- 不得把生产或其他环境的数据导入 `dev`，除非用户明确授权并确认脱敏要求。

### 6.3 非 `dev` 数据库

除 `dev` 外的数据库默认只有可读权限：

- 允许读取数据库列表、schema、表结构、字段、索引和约束。
- 允许执行受限查询和数据核对。
- 禁止 `INSERT`、`UPDATE`、`DELETE`、`MERGE`、`DROP`、`ALTER`、`TRUNCATE`、`CREATE`、批量导入和存储过程调用。
- 禁止通过事务、脚本、函数、触发器或间接调用绕过只读限制。
- 任何写入或结构变更操作必须先完成用户认证，并明确目标环境、对象、SQL、影响范围和回滚方案。

### 6.4 查询安全

- 查询必须尽量限定 schema、表、字段、条件和返回行数。
- 不得默认执行无条件 `SELECT *` 或全表扫描。
- 大表查询应优先使用索引字段、分页和合理的时间范围。
- 查询结果只保留完成任务所需的最小字段和最小行数。
- 发现查询可能涉及个人信息、凭据、财务数据或其他敏感数据时，应先缩小范围或请求用户确认。
- 不得通过 IDEA MCP 输出完整数据库连接串、密码或访问令牌。

## 7. 运行、调试与环境操作

- 启动服务前确认使用的运行配置、端口、环境变量和工作目录。
- 本地开发服务可按项目既有配置启动；修改运行参数前需要用户确认。
- 调试时只设置与问题相关的断点、条件断点和日志断点。
- 不得在日志断点中输出密码、Token、完整请求头或敏感业务数据。
- 修改环境变量时只使用当前任务所需变量，不得覆盖无关变量。
- 访问测试、预发布或生产服务时，默认只允许读取和诊断；任何写操作必须用户认证。
- 不得擅自重启共享服务、清理共享缓存或修改其他用户正在使用的运行环境。

## 8. Git 与外部系统操作

以下操作必须用户明确授权后执行：

- `commit`、`push`、`reset`、`rebase`、`cherry-pick`、删除分支。
- 创建、更新、关闭或合并 Pull Request/Merge Request。
- 修改远程仓库配置、提交钩子或 Git 用户配置。
- 安装依赖、访问外部仓库或执行可能改变工作区之外状态的命令。
- 上传文件、调用外部 API 或向第三方系统写入数据。

执行 Git 或外部系统操作前，应先检查目标仓库、当前分支、工作区状态和远程目标，防止误操作其他项目或分支。

## 9. 认证与确认流程

遇到高风险操作时，按照以下流程处理：

1. 暂停操作，不通过猜测或默认权限继续执行。
2. 说明目标环境、目标对象、具体操作、影响范围和可逆性。
3. 说明需要的认证类型或用户授权内容。
4. 等待用户明确确认或完成认证。
5. 只执行获得授权的操作，不扩大权限和范围。
6. 操作后验证结果，并报告实际影响。

用户认证不等于无限授权。一次认证只覆盖明确说明的目标和操作范围；目标环境、对象或操作类型发生变化时，需要重新确认。

## 10. 变更记录与验证要求

### 10.1 变更前

- 检查当前项目路径和 Git 工作区状态。
- 识别用户已有修改，避免覆盖或回滚。
- 明确本次任务的文件、模块、构建和测试范围。
- 对数据库写操作确认目标环境和影响数量。

### 10.2 变更后

- 查看修改文件和差异，确认没有无关改动。
- 对修改文件执行 IDEA 问题检查或等效静态检查。
- 执行最小范围构建、类型检查或相关测试。
- 对数据库写操作检查受影响记录和结果。
- 报告实际执行的操作、范围、结果、未执行项和残留风险。

### 10.3 结果表述

- 只把实际完成并验证通过的范围表述为已完成。
- “局部构建通过”不能表述为“全项目构建通过”。
- “查询成功”不能表述为“数据库写权限可用”。
- 未执行的测试、构建或环境验证必须明确标记为未验证。

## 11. 快速检查清单

执行 IDEA MCP 操作前，确认：

- [ ] 当前项目路径正确。
- [ ] 已识别用户已有未提交修改。
- [ ] 操作范围是完成任务所需的最小范围。
- [ ] 代码修改没有包含无关重构。
- [ ] 构建没有超出修改涉及的模块。
- [ ] Maven 没有进行不必要的全量加载。
- [ ] 数据库环境已确认；非 `dev` 默认只读。
- [ ] 删除、批量更新、DDL 和其他不可逆操作已完成二次确认。
- [ ] 高风险操作已完成用户认证和明确授权。
- [ ] 已安排局部验证，并准备记录实际结果。
