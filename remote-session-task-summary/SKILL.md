# remote-session-task-summary

本 skill 把"会话内已经做完的开发动作"整理成 2 列分类表格 MD，落到用户指定的 `PM/任务集/*.md` 路径。

## Workflow

1. **锁定会话窗口**：只整理"这次会话内已经做过的"工作；不在窗口内的不写。
2. **扫来源**：从工具调用序列 / 修改的文件 / 创建的 SQL 行 / 写入的数据库里抽"做了什么"。**只写实际动过的**——用户会核对某块（比如"前端你改过吗"），没动过的分类不要凭想象补。
3. **过滤非领导派发**：剔除三类助手自作主张——(a) 初步调研（"读全文找常量"）(b) 自我调试（"\u 转义回滚"）(c) 自验（"三模块编译通过"）。
4. **写功能描述，不写代码**：把"改哪个类哪一行"翻译成人能看懂的一句话。允许出现业务对象名（如"注销申请注意事项""详情页"），禁止出现类名 / 方法名 / 文件名 / 行号 / 表名 / 字段名。
5. **API 只写类型标签**：分类列写 `查询API` / `更新API` / `详情API`，任务列写功能（如"配置表查询入库详情：注意事项读取改为从配置表取"）。**不要贴完整 HTTP 路径**，也不要贴返回字段名。
6. **说清「改的是什么」+「原来是什么」**：每行都要能被非开发同学追问"你到底动了啥"。例：`注意事项读取改为从配置表取，不再存程序内存（重启不丢）`。
7. **合并同物**：同一件事的多个动作（如"源 SQL 加 DDL" + "测试库执行建表"）合并成一行，别拆成"数据表设计"+"环境部署"两行。
8. **生成 MD**：2 列表格，列名固定为 `分类` / `任务`；不放标题 / 备注 / 时间列。
9. **若用户给了剔除规则**：按用户给的规则重做，不要凭记忆。

## Required Constraints

- **2 列固定**：列名固定为 `分类` / `任务`；不放 `工时` / `编号` / `备注` / `负责人` 列。
- **不写标题 / 不写备注 / 不写时间列**：用户明确"只要表格其他都剔除"。
- **纯功能描述**：
  - ✅ `注销店铺清单表没有"平台"字段，清理代码里几处引用该字段的地方`
  - ❌ `StoreEntryPlatformManageServiceImpl L331：删除原依赖 platform 字段的下架检查`
- **API 写法**：分类写 `查询API` / `更新API`；任务写 `配置表查询入库详情：<改了什么>，<原来是什么>`。不贴路径、不贴字段名。
- **每行 = 一个领导派发任务的交付物**：不展开成 HOW 步骤（不写"建 PO / 建 Mapper / 建 Service"）；子步骤用 `；` / `，` 分隔并入同一行。
- **剔除三类非派发**：
  - (a) **助手自作主张的初步调研**——读全文、扫已有结构、找 bug 都是 HOW 过程，不是派发任务
  - (b) **自我调试**——编码回滚、字符乱码修复、连接重试都是 HOW 过程
  - (c) **自验**——编译通过、连接成功、DDL 执行成功都是 HOW 结果
- **不虚构没做的分类**：前端一行没动就不要写"前端展示/适配"；测试环境没跑就不要写"联调"。用户会直接问"这块你改过吗"。
- **领导"纠正"算子条目**：领导说"回滚多余的 2 张表"应并入"回滚"分类行，不单列新任务。
- **合并同物**："设计表"和"建表到库"是同一件事，合并成一行。
- **重复采集不能拿新**：用户说"重新采集"时，重新过一遍"领导派发指令 + 实际写入文件"清单，不要拿上一份抄一遍。

## Response Shape

每次输出：

- 落盘的 MD 路径
- 表格行数（≤ 10 行为佳，> 15 行提示拆分类别）
- 剔除原因（如有，≤ 3 行）
- 若用户问"某块改过没"，先答事实（改过 / 没改过），再决定要不要动表

## 不要做的事

- 不要把助手自查（`introspect` / `lint_files` / `compile` / `build_project`）当成派发任务写进表。
- 不要把"领导纠正"当作新任务——它是父任务的子条目。
- 不要贴类名 / 方法名 / 文件路径 / 行号 / 表名 / SQL 语句到任务描述里。
- 不要贴完整 API 路径（`GET /cashier/...`）——只写 `查询API` / `更新API` 类型标签。
- 不要写"前端适配"这类没验证过的分类——先确认本会话是否真动过前端文件。
- 不要替用户挑 MD 路径——按用户给的绝对路径写。
- 不要把"会话外"的工作（之前会话做过的、本轮没出现的）写进当前会话的快照。

## 常见返工信号（用户会这么说）

| 用户原话 | 含义 | 改法 |
|---|---|---|
| `不要写代码相关懂吗，用人能看懂写功能描述` | 任务列混进了类名/行号 | 全部翻译成业务语言 |
| `我意思是，这是一个查询API的话，描述：查询API：配置表查询入库详情` | 要类型标签，不要完整路径 | 分类列写 `查询API`，任务列写功能 |
| `数据表设计和环境部署 是同一个东西合并` | 同一件事被拆成两行 | 合并成一行 |
| `现状调研去除，没有这个东西` | 分类是助手自造的，不是领导派的 | 删掉 |
| `前端某某适配描述，你是否改过，改过也算任务` | 分类写了但没真做 | 没做过就删，做过才留 |
| `你说的那个东西是改的什么啊，写清楚啊` | 任务列只写了动作没写对象 | 补「改的是什么 + 原来是什么」 |
