## 四、关键发现：`setupVxeRenderers()` 注册情况（P0）

> ✅ **2026-07-31 修正**：初始扫描（Agent ④）只 grep 了 `setupVxeRenderers` 字面量，误判为"未调用"。核实 `BiWebCommonPlugin`（`packages/share/exports/plugin.ts`）的 `install()` 内部已调用 `setupVxeRenderers()`，且 `main.ts:93` 已 `app.use(BiWebCommonPlugin)`。**该渲染器注册在启动时已生效，P0 无需改动。**

`SHARE_COMPONENTS.md` 要求应用启动时调用一次 `setupVxeRenderers()`，注册 6 个自定义 vxe 渲染器（`ElInput / ElSelect / ElInputNumber / ElDatePicker / Upload / NumberRange`）。

- **现状**：已通过 `BiWebCommonPlugin` 注册；全库 `editRender` / `createFieldRenderer` **零使用**（现有页面用不到这些渲染器）。
- **影响**：当前无显性问题；引入 `CommonVxeTable` 行内编辑或列配置 `editRender` 使用 `Upload`/`NumberRange` 渲染器时可直接生效。
- **后续**：若确认渲染器注册目标与 `plugins/vxe-table.ts` 桥接的共享 VxeUI 单例一致即可（当前页面表格渲染正常，已间接验证）。

## 八、附录

### 8.1 DynamicForm 内置类型缺口（共享组件侧建议）

`FormItemType` 声明了 `time` / `switch`，但 `componentsMap` 未映射，会被兜底渲染为 `el-input`（文档"已知问题"第 1 条）。当前业务方统一用 `type: ElSwitch` / `type: ElInputNumber` 传组件实例规避（seal/addOrEdit、store/addOrEdit、bankCard/addOrEdit、employee/addOrEdit）。**若共享组件侧补上 `switch` / `input-number` 字符串类型映射，各处插槽可进一步收敛**——属共享包改动，非本子应用范围。

### 8.2 命令式弹窗迁移注意事项

- 弹窗内组件需暴露 `submit(): Promise<boolean>`（true 关闭、false 保持打开）；确认按钮自动 loading。
- 批量/详情场景需要把选中数据作 props 传入（如 SetExpirationModal 的 `unNameList`）。
- 依赖 `watch(props.visible)` 打开时加载下拉/详情的逻辑，迁移后需移到 `onMounted`（命令式每次新建挂载）。

### 8.3 扫描方法

- 4 个并行 agent 按模块组扫描：① bankCard/employee/store；② company/seal；③ fileExpiration/ruleManagement/businessScope；④ Attachment/dashboard/login/layouts/plugins。
- 对照 `SHARE_COMPONENTS.md` 逐文件核对 import 与模板组件。
